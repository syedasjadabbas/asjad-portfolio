TuneBox

A cross-platform Flutter audio streaming and local playback client featuring a unified media model, reactive GetX state orchestration, Just Audio streaming, and cloud synchronization via Supabase PostgreSQL.

Role Mobile Engineering Intern
Focus Audio Engine & Reactive Architecture
Context SVYPE Internship · May 2026 – Jul 2026
Core Stack Flutter · Dart 3.5 · GetX · Just Audio · Supabase

Problem & Engineering Challenge

Mobile audio applications are among the most state-sensitive software to engineer. Unlike static CRUD apps, media players deal with asynchronous hardware events, continuous sub-second playback time updates, operating system audio focus interrupts, and background service execution constraints.

During my mobile engineering internship at SVYPE, TuneBox faced three significant architectural challenges:

  • Disparate Audio Sources: The application needed to support both on-device audio files scanned from mobile storage (MediaStore) and cloud-hosted tracks streamed remotely. Prior implementations treated these as separate subsystems with duplicated playback logic.
  • State Drift Between Full-Screen & Mini-Player Views: Playback position, track metadata, and play/pause states frequently desynchronized when users transitioned between the expanded player view and the bottom navigation mini-player bar.
  • UI Jank from Uncontrolled Rebuilds: High-frequency stream updates (such as seekbar position ticks occurring every 200 milliseconds) were triggering cascading widget re-renders across parent navigation screens.
  • Modern Android Storage Restrictions: Android 13+ (API 33) introduced granular media permissions (READ_MEDIA_AUDIO), causing legacy storage scanning logic to throw security exceptions on newer devices.

Unified Media Architecture & Stream Pipeline

To eliminate state duplication and deliver smooth 60fps playback rendering, I restructured the application around a decoupled reactive architecture combining GetX, Just Audio, and an atomic UnifiedSong abstraction layer:

Engineering Challenges & Technical Solutions

1. Polymorphic Audio Abstraction (UnifiedSong)

Initially, local tracks (represented as SongModel by OnAudioQuery) and remote tracks (represented as MySongModel from cloud storage) required distinct controllers, separate playlist tables, and duplicate seekbar interfaces.

Solution: I designed a unified domain model, UnifiedSong, featuring polymorphic factory constructors: UnifiedSong.fromLocal(SongModel) and UnifiedSong.fromCloud(MySongModel). Each instance generates a deterministic composite identifier key (e.g., local-1042 or cloud-88).

This single abstraction allowed the core Songplayercontroller, the user's custom playlists, and the favorites subsystem to treat local MP3s and remote HTTP streams identically across the entire application.

2. Zero-Jank Reactive UI via GetX Observables

Audio playback updates position continuously. Using conventional setState() or naive parent listeners caused the entire navigation tree and background canvas to re-render repeatedly, causing stutter on mid-range Android devices.

Solution: Converted the audio lifecycle into pure reactive streams using GetX observables (RxBool, RxString, Rxn<UnifiedSong>). The controllers were registered as permanent singletons within RootShell (Get.put(..., permanent: true)).

In the UI, rebuilds are isolated strictly to microscopic Obx(() => ...) wrappers surrounding only the seekbar thumb and elapsed time text nodes. As a result, 60fps scrolling and fluid animations remain completely unaffected during audio playback.

3. Granular Android 13+ Scoped Storage & Permission Fallbacks

Devices running Android 13 (API 33) and above reject legacy READ_EXTERNAL_STORAGE permissions, causing runtime permission crashes when querying local music.

Solution: In SongDataController.initLocalSongs(), implemented a defensive dual-tier permission resolution pipeline using permission_handler and OnAudioQuery status checks:

  • Automatically checks and requests Android 13+ granular media audio permission (Permission.audio).
  • Gracefully falls back to legacy storage permissions (Permission.storage) on Android 12 and below.
  • Wraps the entire query in try-catch error guards to prevent cold-start crashes if a user denies media access, allowing the user to continue streaming cloud tracks uninterrupted.

4. Cloud Sync via Supabase RPCs & Row-Level Security

User favorites and playlist management needed to persist across app reinstalls and synchronize across devices without requiring complex custom backend infrastructure.

Solution: Leveraged Supabase (PostgreSQL) with Row-Level Security (RLS) policies and PL/pgSQL stored procedures:

  • Automated User Provisioning: Created a PostgreSQL trigger on auth.users (handle_new_user / ensure_user_profile) that automatically provisions a public user profile upon sign-up or sign-in.
  • Atomic Stored Procedures: Implemented PL/pgSQL RPC functions (toggle_favorite, create_playlist, add_song_to_playlist, remove_song_from_playlist) so mobile clients perform multi-table writes in a single roundtrip.
  • Dynamic Auth Re-sync: Subscribed to _supabase.auth.onAuthStateChange in RootShell, automatically reloading user playlists and favorites on login and clearing cached records on logout.

SVYPE Internship Impact & Component Refactor

As part of my core deliverables at SVYPE, I conducted an end-to-end refactoring of the existing Flutter UI layer. By extracting reusable UI widgets (SongAndVolume, SongTile, TrendingSong, and PlaySongHeaderButton) and migrating scattered state logic into reactive controllers, frontend complexity was substantially reduced.

This architectural cleanup eliminated duplicated seekbar mathematics and solved audio state desynchronization between full-screen and mini-player modes.

Key Takeaways & Engineering Impact

TuneBox illustrates that mobile audio performance depends heavily on architecture rather than raw device horsepower. By isolating high-frequency stream events from static UI widgets, abstracting disparate audio origins into a single polymorphic domain model, and offloading multi-step state mutations to PostgreSQL stored procedures, the application achieves instantaneous playback transitions and stable 60fps performance.
